Both entries cite the same PR and both describe `text_source` handling being fixed; the generic Default entry looks like it may duplicate the specific ai-aws-guardrails entry rather than describe a separate plugin's fix. Recommend the reviewer confirm scope before keeping both.

- _"**ai-proxy-advanced**: Fixed an issue where provider-reported reasoning-token details were not correctly reported."_ versus _"**ai-proxy-advanced**: Fixed an issue where xAI reasoning tokens were not folded into `completion_tokens`, breaking the OpenAI usage identity."_ (both PR #22059, both AG-1420). ## Flagged for security review

- _"**datakit**: Fixed CVE-2026-14916 by binding the JWT algorithm to the
verification key's type in the `jwt_verify` node, so a symmetric algorithm can
no longer be verified against an asymmetric key, preventing an authentication
bypass where an attacker forges tokens by using the public key as an HMAC
shared secret, under configurations where the node uses a PEM key string and
`allowed_algorithms` is unset (any algorithm accepted)."_ — this entry names the exact exploit technique (using the public key as an HMAC shared secret) and the precise vulnerable configuration (PEM key string with `allowed_algorithms` unset). This reads closer to a reproduction recipe than a generic description of the fix; flagging for a judgment call on how much detail is safe to publish.

- _"**SAML**: Fixed CVE-2026-14917 by validating the `samlp:Response` signature whenever
an `idp_certificate` is configured -- even when `validate_assertion_signature` is
disabled -- and logging a warning when neither is set, preventing an unauthenticated
attacker from impersonating any user with a crafted unsigned SAML response, under
configurations that set `validate_assertion_signature` to `false`."_ — this entry describes the exact bypass condition (`validate_assertion_signature` set to `false`) and the attack outcome (impersonating any user with a crafted unsigned SAML response) in enough detail to guide exploitation. Flagging for a judgment call on exposure.

- _"**SAML**: Hardened signature validation against XML Signature Wrapping. The
plugin now checks that the signature `Reference URI` is a same-document
fragment that names the `ID` of the element it digests and consumes, so a
signature can no longer be bound to a different element than the one that
provides the identity. A response whose reference URI is empty or not a
same-document fragment is now rejected."_ — no CVE number given, but this describes an XML Signature Wrapping hardening in mechanism-level detail (the specific `Reference URI` validation logic). Flagging since it explains the prior weakness precisely enough to imply how the class of attack worked, alongside the related CVE-2026-14917 entry above.

- _"**oauth2-introspection**: Fixed an authentication bypass where a revoked or
expired token stayed authorized indefinitely instead of being rejected. An
authoritative `active:false` result is now also cached briefly (5 seconds)."_ — labeled an "authentication bypass" and describes the exact caching gap that caused it. Flagging for a judgment call on whether the level of detail (the specific 5-second caching mechanic) is appropriate to publish given no CVE is cited.
