This guide builds on [Map a RESTful API to MCP tools](/ai-gateway/map-api-to-mcp-tools/). Complete that guide first so the `marketplace-mcp` MCP Server entity and mock API already exist.

## Reconfigure the MCP Server entity

To observe traffic for MCP tools, enable [`logging.payloads`](/ai-gateway/entities/ai-mcp-server/#schema-aigateway-mcp-server-config-logging-payloads) and [`logging.statistics`](/ai-gateway/entities/ai-mcp-server/#schema-aigateway-mcp-server-config-logging-statistics) on the `marketplace-mcp` MCP Server entity:

```sh
kongctl apply -f - --auto-approve --pat "$KONNECT_TOKEN" <<EOF
ai_gateways:
  - ref: ai-quickstart
    _external:
      selector:
        matchFields:
          name: "ai-quickstart"

ai_gateway_mcp_servers:
  - ref: marketplace-mcp
    ai_gateway: ai-quickstart
    name: marketplace-mcp
    display_name: "Marketplace API"
    type: conversion-listener
    enabled: true
    policies:
      - !ref mcp-prometheus#name
    access:
      acl_attribute_type: consumer
      acls:
        allow: []
      default_tool_acls:
        deny: []
    config:
      url: http://host.docker.internal:3000
      route:
        paths:
          - /marketplace
      logging:
        payloads: true
        statistics: true
      server:
        timeout: 60000
    tools:
      - name: get-users
        description: Get users
        method: GET
        path: /marketplace/users
        parameters:
          - name: id
            in: query
            required: false
            schema:
              type: string
            description: Optional user ID
      - name: get-orders-for-user
        description: Get orders for a user
        method: GET
        path: /marketplace/orders
        parameters:
          - description: User ID to filter orders
            in: query
            name: userid
            required: true
            schema:
              type: string

ai_gateway_policies:
  - ref: mcp-prometheus
    ai_gateway: ai-quickstart
    name: mcp-prometheus
    display_name: "MCP Prometheus"
    type: prometheus
    enabled: true
    global: false
    config:
      status_code_metrics: true
      ai_metrics: true
EOF
```

## Configure Prometheus

Create a `prometheus.yml` file to scrape MCP traffic metrics from your data plane's status port:

```sh
cat <<EOF > prometheus.yml
scrape_configs:
 - job_name: 'kong'
   scrape_interval: 5s
   static_configs:
     - targets: ['kong-quickstart-gateway:8100']
EOF
```

Run a Prometheus server, and pass it the configuration file created in the previous step:

```sh
docker run -d --name kong-quickstart-prometheus \
  --network=kong-quickstart-net -p 9090:9090 \
  -v $(PWD)/prometheus.yml:/etc/prometheus/prometheus.yml \
  prom/prometheus:latest
```

Prometheus will begin to scrape metrics data from {{site.ai_gateway}}.

## Validate the configuration

You can validate that the Prometheus policy is collecting metrics by generating MCP traffic against `marketplace-mcp`. Enter the following question in the ChatWise chat:

```text
What users do you see in the API?
```

Once the ChatWise agent has finished reasoning, run the following to query the collected `kong_ai_mcp_latency_ms` metric data:

```sh
curl -s 'localhost:9090/api/v1/query?query=kong_ai_mcp_latency_ms_bucket'
```
