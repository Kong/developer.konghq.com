An agent is a software system that uses AI to act on its own or on behalf of a user.
When an agent calls your {{site.ai_gateway}} models and MCP servers, it needs its own identity, so that you can control what it reaches and see what it spends without sharing the credentials of the users who manage it.

An agent identity gives an agent its own credentials, [access rules](#access-rules), and [spend limit](#set-a-spend-limit).
{{site.ai_gateway}} attributes the requests made with the agent's credentials to the agent.

An agent identity doesn't expose the agent through {{site.ai_gateway}}.
To let users and other agents call your agent through the gateway, create an [AI Agent](/ai-gateway/entities/ai-agent/).

## Create an agent identity

Admins create agent identities manually.
To create an agent identity, do the following:

1. In the {{site.konnect_short_name}} sidebar, click **Access Management**.
1. In the Access Management sidebar, click **Agents**.
1. Click **Create agent identity**.
1. In the **Name** field, enter a name for the agent, like `booking-agent`.
1. Optional: To add a credential now, click **Add identity source**. See [Identity sources](#identity-sources).
1. Click **New agent**.

An agent identity also has a description, labels, a cost center, and metadata:

* **Cost center:** Where the agent's spend is charged, like `Customer support`. If it's empty, the agent's spend stays unattributed. In the {{site.identity}} API, it's stored in the principal's metadata as `cost_center`.
* **Metadata:** Key-value pairs. Each value is a string, a number, a Boolean, or a list.

To change any of them later, select "Edit" from the identity's **Actions** dropdown menu.

In the {{site.identity}} API, an agent identity is a [principal](/identity/principals/) with `type` set to `agent`.
The type can't be changed after creation, so a user can't be converted into an agent.

## Identity sources

An agent identity's identity sources define how {{site.ai_gateway}} recognizes the agent when it calls models, MCP servers, or other agents.
In the {{site.identity}} API, they're the principal's [credentials and identities](/identity/principals/#principal-configuration).

Identity sources are optional when you create the identity.
To add one, click **Add identity source**, then choose an **Authentication type**.
To add one later, select "Edit" from the identity's **Actions** dropdown menu, then click **Add authentication**.

## Access rules

An agent identity can't call any model or MCP server until an access rule allows it.
When no rule matches, access is denied, and a rule that denies access wins over a rule that allows it.
Rules apply to the agent directly, or through the [groups](/ai-access-management/concepts/#groups) it belongs to.

To let the agent call a model, do the following:

1. In the {{site.konnect_short_name}} sidebar, click **Access Management**.
1. In the Access Management sidebar, click **Agents**.
1. Click the agent identity.
1. In the **Access** section, click **Add access rule**.
1. Click the **Model** tab.
1. From the **Model** dropdown menu, select the model that the agent calls.
1. Select **Allow**.
1. In the **Display name** field, enter a name for the rule, like `Booking agent: OpenAI Chat`.
1. Click **Add access rule**.

To cover every model of a provider, click the **A whole provider** tab instead of selecting models.
To let the agent call an MCP server, click the **MCP server** tab instead of the **Model** tab.

Gateways apply a new or changed access rule the next time they refresh the caller, which can take a few minutes.
Access rules apply only to authenticated requests.
Access rules don't control calls to other agents: an AI Agent's auth strategy and [ACL](/ai-gateway/entities/ai-agent/#cel-based-acls) define who can call it.

## Set a spend limit

An agent identity's spend limit caps what the agent spends on {{site.ai_gateway}} resources.
To set it, click **Set spend limit** on the identity's page.
The lowest limit set on the agent or on its groups applies.

## Deactivate an agent identity

A deactivated agent identity can't authenticate until you reactivate it, and its credentials are kept.
A gateway that has cached the agent's credentials may keep allowing access until the cache expires.
To deactivate an agent identity, select "Deactivate" from the identity's **Actions** dropdown menu.
