## Problem

You notice your Mesh data plane is not functioning correctly, failing to communicate with the control plane.

A review of the DP logs shows the below error.

```
2026-12-30T12:13:14.632Z ERROR component terminated with an error {"generationID": 478677, "error": "could not connect to OPA DS: rpc error: code = Unavailable desc = connection error: desc = \"transport: authentication handshake failed: x509: certificate signed by unknown authority (possibly because of \\\"crypto/rsa: verification error\\\" while trying to verify candidate authority certificate \\\"kuma-ca\\\")\"",

[2026-12-30T12:13:14.644Z][25][warning][config] [./source/common/config/grpc_stream.h:196] StreamAggregatedResources gRPC config stream closed since 2392948s ago: 14, upstream connect error or disconnect/reset before headers. reset reason: connection failure, transport failure reason: TLS error: 268435581:SSL routines:OPENSSL_internal:CERTIFICATE_VERIFY_FAILED
```

## Cause

This error typically occurs when using tooling, such as Argo CD or Harness SD, with your Helm deployments.

A note from the documentation:

```
Kuma requires a certificate to verify a connection between the control plane and a data plane proxy. The Kuma Helm chart autogenerates a self-signed certificate if the certificate isn’t explicitly set.
```

Tools such as Argo and Harness use the `helm template` command to apply the YAML. This command does not work with the chart logic to verify if the certificate is present which results in the certificate being replaced on each deployment.

## Solution

To resolve this problem you will need to provide your certificate in your deployment values file. This will prevent these systems from autogenerating the certificate on restart.

If you are receiving this error, your certificates should have already been generated. However, if not, you can follow this guide to do so.

Once you have your certificates you can update your values to include the below settings:

- Set `controlPlane.tls.general.secretName` to your `kong-mesh-tls-cert` secret
- Extract `tls.crt` from this secret and pass it to `controlPlane.tls.general.caBundle`

```bash
kubectl get secrets kuma-tls-cert -ojsonpath='{.data.tls\.crt}'
```

```yaml
ControlPlane:
  tls:
    general:
      secretName: kong-mesh-tls-cert
      caBundle: LS0tLS1CRUdJTiBDRVJUSUZJ.....
```
